Database SQL Basics

Tables, rows, columns, and your first SQL queries — SELECT, FROM, WHERE, ORDER BY.

Blue Team Software Basics SQL
01 — Introduction

Why Databases?

A small café tracks orders in a paper notebook. It works at first — but as orders grow, answering questions like "How many coffees sold today?" requires reading every page manually. This is slow and error-prone.

A database is a digital storage system that keeps information organised so a computer can search, count, and sort it in milliseconds — even across millions of records.

SQL (Structured Query Language) is the language used to ask questions to a database. It is not a programming language like Python or JavaScript — it is a query language: you describe what data you want, and the database retrieves it.

Key Takeaway

Database = organised digital storage. SQL = the language to ask it questions. A query does not change data — it only reads and displays what you requested.

02 — Tables, Rows, and Columns

The Structure of a Database

Inside a database, all information is stored in tables — similar to spreadsheets. Every table has a name and is made of:

  • Columns — the titles at the top. Each column stores one type of information (e.g. drink name, price, time).
  • Rows — each row is one complete record (e.g. one café order).

Example: the Orders table

IDDrinkPriceTime
1Coffee2.0011:00 AM
2Tea1.5011:10 AM
3Muffin2.5011:15 AM
4Coffee2.0012:05 PM
5Tea1.5012:30 PM
  • Row 3 (highlighted) = one complete order: Muffin, £2.50, at 11:15 AM.
  • The Price column stores only prices — nothing else.
  • Adding a new order = adding one row. Removing an order = removing one row. The rest of the table is unaffected.
Key Takeaway

Table = one category of data (e.g. orders). Column = one type of info (e.g. price). Row = one complete record (e.g. one order). One column stores all information about one order.

03 — Writing Your First SQL Query

SELECT · FROM · WHERE · ORDER BY

SQL queries are built from clauses. Each clause has a specific role. You combine them to precisely describe the data you want.

SQL Query Anatomy

SELECT drink, price FROM Orders WHERE drink = 'Coffee' ORDER BY price DESC;
Step 1

SELECT

Chooses which columns to display. Use * to select all columns, or list specific names separated by commas.

Step 2

FROM

Tells the database which table to look in. Always required. Example: FROM Orders

Step 3

WHERE

Filters rows — only rows matching the condition are returned. Optional but very common. Example: WHERE drink = 'Coffee'

Step 4

ORDER BY

Sorts results by a column. Default is ascending (lowest first). Add DESC for descending (highest first).

Step 1 — View Everything (SELECT *)

SELECT * FROM Orders;

Returns every column and every row in the Orders table. * is a wildcard meaning "all columns".

Step 2 — Select Specific Columns

SELECT drink, price FROM Orders;

Returns only the drink and price columns — ignores ID and Time.

Step 3 — Filter Results (WHERE)

SELECT * FROM Orders WHERE drink = 'Coffee';

Returns only rows where the drink is Coffee. String values are wrapped in single quotes ' '.

-- Note: use column names, not string values, without quotes SELECT * FROM Orders WHERE price < 2.00;

Step 4 — Sort Results (ORDER BY)

-- Ascending (lowest first — default) SELECT * FROM Orders ORDER BY price; -- Descending (highest first) SELECT * FROM Orders ORDER BY price DESC;

Step 5 — Combine Filtering + Sorting

SELECT * FROM Orders WHERE drink = 'Coffee' ORDER BY price DESC;

Filters to show only Coffee orders, then sorts them from most expensive to cheapest.

Key Takeaway

SQL clause order matters: SELECT → FROM → WHERE → ORDER BY. SELECT * = all columns. WHERE filters rows. ORDER BY col DESC sorts highest-first. String values need single quotes; numbers don't.

Security Note

Why SQL Matters in Cybersecurity

The conclusion of the room asks: "What could happen if someone were allowed to change or remove café orders without permission?"

This points directly to a critical web vulnerability: SQL Injection (SQLi). If a web application passes user input directly into a SQL query without sanitisation, an attacker can manipulate the query to:

  • Bypass authentication (login without a password)
  • Dump entire database contents (usernames, passwords, credit cards)
  • Delete or modify records
  • In some cases, execute commands on the server

Understanding how SQL queries are structured is the first step to understanding how SQL injection attacks work and how to defend against them.

Key Takeaway

SQL knowledge is essential for web security. SQL Injection is consistently in the OWASP Top 10 most critical web vulnerabilities. You cannot understand or prevent it without first understanding how normal SQL queries work.

Vocabulary

Key Terms

  • Database — An organised collection of structured data stored and managed by a computer. Allows fast search, sort, and retrieval.
  • SQL — Structured Query Language. The standard language for interacting with relational databases.
  • Query — A question asked to a database. A query reads data — it does not modify it (unless using INSERT/UPDATE/DELETE).
  • Table — A structured collection of data in a database, organised into rows and columns. Like a spreadsheet.
  • Column — A vertical attribute in a table. Defines one type of information (e.g. price, drink).
  • Row — A horizontal record in a table. Contains one complete entry (e.g. one café order).
  • SELECT — SQL clause that specifies which columns to return.
  • FROM — SQL clause that specifies which table to query.
  • WHERE — SQL clause that filters rows based on a condition.
  • ORDER BY — SQL clause that sorts results by a column. Default: ascending. Add DESC for descending.
  • * (wildcard) — In SQL, SELECT * returns all columns.
  • ASC / DESC — Ascending (lowest → highest) / Descending (highest → lowest). Used with ORDER BY.
  • SQL Injection — A web attack that manipulates SQL queries by injecting malicious input. One of the most common and dangerous web vulnerabilities.
  • Relational Database — A database that stores data in tables that can be linked (related) to each other.

What is a database?
An organised digital storage system that lets a computer search, count, and sort information very quickly — even across millions of records.
What does SQL stand for? Is it a programming language?
Structured Query Language. It is not a programming language — it is a query language. You describe what data you want, and the database retrieves it.
What is a table in a database?
A structured set of data organised into rows and columns, similar to a spreadsheet. Each table stores one category of information (e.g. Orders).
What is a column? What is a row?
A column defines one type of information (e.g. price). A row is one complete record (e.g. one café order). A table has many rows and a fixed set of columns.
What does SELECT * FROM Orders do?
Returns every column (*) and every row from the Orders table. The * wildcard means "all columns".
What does the WHERE clause do?
It filters rows — only rows that match the condition are returned. Example: WHERE drink = 'Coffee' returns only coffee orders.
How do you select only the drink and price columns from Orders?
SELECT drink, price FROM Orders;
How do you sort results from highest price to lowest?
ORDER BY price DESC — DESC means descending (highest first). Without DESC, results are sorted ascending (lowest first) by default.
What is the correct order of SQL clauses?
SELECT → FROM → WHERE → ORDER BY. The order matters — writing them out of sequence causes a syntax error.
String values in SQL need what kind of quotes?
Single quotes ' '. Example: WHERE drink = 'Coffee'. Numbers do not need quotes: WHERE price = 2.00
Write a query to show all orders where the drink is Tea, sorted by time ascending.
SELECT * FROM Orders WHERE drink = 'Tea' ORDER BY time;
Does a SELECT query modify data?
No. SELECT only reads and displays data. Modifying data requires other commands: INSERT (add), UPDATE (change), DELETE (remove).
What is SQL Injection and why is it dangerous?
A web attack where malicious SQL is injected into a query via unsanitised user input. It can bypass authentication, leak entire databases, or delete records. Consistently in the OWASP Top 10.
What is the term for the "spreadsheets" that store information inside a database?
Tables.
