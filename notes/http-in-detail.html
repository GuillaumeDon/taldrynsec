How The Web Works

HTTP in Detail

Learn how you request content from a web server using the HTTP protocol.

Networking Beginner
01 — The Protocol of the Web

What is HTTP(S)?

HTTP (HyperText Transfer Protocol) is used whenever you view a website. Developed by Tim Berners-Lee and his team between 1989-1991, HTTP is the set of rules used for communicating with web servers for the transmitting of webpage data — HTML, images, videos, etc.

HTTPS (HyperText Transfer Protocol Secure) is the secure version of HTTP. HTTPS data is encrypted so it not only stops people from seeing the data you are receiving and sending, but it also gives you assurances that you're talking to the correct web server and not something impersonating it.

Key Takeaway

HTTP = data in plain text (anyone can read it). HTTPS = data encrypted (private + verified server identity). The "S" stands for Secure. Always look for the padlock icon in your browser.

02 — How Communication Works

Requests and Responses

What is a URL? (Uniform Resource Locator)

A URL is predominantly an instruction on how to access a resource on the Internet. Here's what a full URL looks like with all its features:

http://user:password@tryhackme.com:80/view-room?id=1#task3
  • Scheme — What protocol to use: HTTP, HTTPS, FTP (File Transfer Protocol).
  • User — Some services require authentication. You can put a username and password into the URL to log in.
  • Host — The domain name or IP address of the server you wish to access.
  • Port — The port to connect to, usually 80 for HTTP and 443 for HTTPS. Can be any port between 1-65535.
  • Path — The file name or location of the resource you are trying to access.
  • Query String — Extra bits of information sent to the requested path. For example, /blog?id=1 would tell the blog path to receive the article with id 1.
  • Fragment — A reference to a location on the actual page requested. Commonly used for pages with long content to link directly to a certain part of the page.

Making a Request

A request can be made with just one line: GET / HTTP/1.1. But for a richer experience, you'll need headers too.

Example Request

GET / HTTP/1.1
Host: tryhackme.com
User-Agent: Mozilla/5.0 Firefox/87.0
Referer: https://tryhackme.com/

  • Line 1 — GET method, requesting the home page /, using HTTP protocol version 1.1.
  • Line 2 — Which website we want (Host).
  • Line 3 — What browser we're using.
  • Line 4 — The web page that referred us.
  • Line 5 — Blank line to inform the server the request has finished.

Example Response

HTTP/1.1 200 OK
Server: nginx/1.15.8
Date: Fri, 09 Apr 2021 13:34:03 GMT
Content-Type: text/html
Content-Length: 98

<html>...page content...</html>
  • Line 1 — HTTP version 1.1 + Status Code 200 OK (request completed successfully).
  • Line 2 — Web server software and version number.
  • Line 3 — Current date, time and timezone.
  • Line 4 — Content-Type tells the client what sort of information is going to be sent (HTML, images, PDF, etc.).
  • Line 5 — Content-Length tells the client how long the response is, so we can confirm no data is missing.
  • Line 6 — Blank line to confirm the end of the response headers.
  • Lines 7+ — The actual requested content (the HTML page).
03 — The Verbs

HTTP Methods

HTTP methods are a way for the client to show their intended action when making a request. The most common ones:

GET
Used for getting information from a web server. Reading a page, viewing an article.
POST
Used for submitting data to the web server and potentially creating new records. Creating a user account, submitting a form.
PUT
Used for submitting data to update information. Updating your email address, changing a profile.
DELETE
Used for deleting information/records from a web server. Removing a picture, deleting an account.
Quick Rule

GET = read. POST = create. PUT = update. DELETE = delete. This maps to CRUD operations (Create, Read, Update, Delete) — a fundamental concept in web development and APIs.

04 — The Server's Answer

HTTP Status Codes

The first line of an HTTP response always contains a status code informing the client of the outcome. Status codes are broken into 5 ranges:

RangeCategoryMeaning
100-199InformationFirst part of request accepted, continue sending. No longer very common.
200-299SuccessRequest was successful.
300-399RedirectionRedirect the client to another resource (different page or website).
400-499Client ErrorsThere was an error with the client's request.
500-599Server ErrorsErrors on the server-side. Usually indicates a major problem.

Common Status Codes to Memorize

CodeNameDescription
200OKRequest completed successfully.
201CreatedA resource has been created (e.g. a new user or blog post).
301Moved PermanentlyRedirects the browser to a new URL permanently. Search engines update their links.
302FoundTemporary redirect. The change may revert in the near future.
400Bad RequestSomething was wrong or missing in the client's request.
401Not AuthorisedNot currently allowed to view this resource until you have authorised (logged in).
403ForbiddenYou do not have permission to view this resource whether you're logged in or not.
404Page Not FoundThe page/resource you requested does not exist.
405Method Not AllowedThe resource doesn't allow this method (e.g. you sent a GET but it expects a POST).
500Internal Service ErrorThe server encountered an error it doesn't know how to handle.
503Service UnavailableServer cannot handle the request — overloaded or down for maintenance.
Key Takeaway

Remember the ranges: 2xx = good, 3xx = redirect, 4xx = your fault, 5xx = server's fault. The most important to memorize: 200, 301, 302, 400, 401, 403, 404, 500, 503.

05 — Extra Information

Headers

Headers are additional bits of data you can send to the web server when making requests. Although no headers are strictly required, you'll find it difficult to view a website properly without them.

Common Request Headers (Client → Server)

  • Host — Which website you require. Some servers host multiple sites, so this tells them which one.
  • User-Agent — Your browser software and version. Helps the server format the website properly for your browser.
  • Content-Length — How much data the client is sending (e.g. in a form submission). So the server knows it isn't missing any data.
  • Accept-Encoding — What compression methods the browser supports so data can be made smaller for transmission.
  • Cookie — Data sent to the server to help remember your information (see Cookies task).

Common Response Headers (Server → Client)

  • Set-Cookie — Information to store which gets sent back to the web server on each subsequent request.
  • Cache-Control — How long to store the content of the response in the browser's cache before requesting it again.
  • Content-Type — What type of data is being returned (HTML, CSS, JavaScript, Images, PDF, Video, etc.). The browser uses this to know how to process the data.
  • Content-Encoding — What compression method has been used to make the data smaller when sending over the Internet.
06 — Remembering You

Cookies

Cookies are small pieces of data stored on your computer. They are saved when you receive a "Set-Cookie" header from a web server. Then every further request you make, you'll send the cookie data back to the web server.

Why Cookies Exist

Because HTTP is stateless (doesn't keep track of your previous requests), cookies can be used to remind the web server who you are, your personal settings, or whether you've been to the website before.

Cookie values won't usually be a clear-text string like a password — instead, it's a token (unique secret code that isn't easily humanly guessable).

Viewing Cookies

You can view cookies your browser is sending by using the Developer Tools in your browser (F12 → Network tab → click on a request → Cookies tab).

Key Takeaway

Cookies add statefulness to the stateless HTTP protocol. The header Set-Cookie saves cookies to your computer. On every subsequent request, the Cookie header sends them back. Cookies are used for authentication, preferences, and tracking — and are a major topic in web security (cookie theft, session hijacking).

Vocabulary

Key Terms

  • HTTP — HyperText Transfer Protocol. Rules for web communication. Data in plain text.
  • HTTPS — HTTP Secure. Encrypted version. The "S" = Secure.
  • URL — Uniform Resource Locator. The full address to access a resource on the Internet.
  • Scheme — The protocol part of a URL (http, https, ftp).
  • Host — The domain name or IP in the URL.
  • Port — The door to connect to (80 for HTTP, 443 for HTTPS).
  • Path — The specific resource/page being requested.
  • Query String — Extra parameters after ? in the URL (e.g. ?id=1).
  • Fragment — Reference to a specific location on the page (after #).
  • GET — Retrieve information (read).
  • POST — Submit data / create new records.
  • PUT — Update existing information.
  • DELETE — Remove information/records.
  • CRUD — Create (POST), Read (GET), Update (PUT), Delete (DELETE).
  • Status Code — Numerical code in the response indicating success or failure.
  • 2xx — Success. 3xx — Redirection. 4xx — Client error. 5xx — Server error.
  • Headers — Additional metadata sent with requests and responses.
  • User-Agent — Header identifying the browser software.
  • Content-Type — Header identifying the type of data being returned.
  • Cookie — Small piece of data stored on the client, sent back with every request.
  • Set-Cookie — Response header that tells the browser to save a cookie.
  • Token — A unique secret code used as a cookie value instead of plain text passwords.
  • Stateless — HTTP doesn't remember previous requests by default. Cookies fix this.
