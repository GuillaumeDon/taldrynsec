How Websites Work

To exploit a website, you first need to know how they are created.

Web Security Beginner
01 — The Big Picture

How Websites Work

When you visit a website, your browser (like Safari or Chrome) makes a request to a web server asking for information about the page you're visiting. The server responds with data that your browser uses to show you the page. A web server is just a dedicated computer somewhere else in the world that handles your requests.

Two Major Components

Front End (Client-Side)
The way your browser renders a website. What you see and interact with. Built with HTML, CSS, and JavaScript.
Back End (Server-Side)
A server that processes your request and returns a response. Handles logic, databases, authentication, etc.
Key Takeaway

Front end = what your browser displays (client-side). Back end = server processing your request (server-side). Understanding both is essential for web security — vulnerabilities exist on each side.

02 — The Structure

HTML

Websites are primarily created using three technologies:

  • HTML — to build websites and define their structure
  • CSS — to make websites look pretty by adding styling options
  • JavaScript — to implement complex features on pages using interactivity

HyperText Markup Language (HTML) is the language websites are written in. Elements (also known as tags) are the building blocks of HTML pages and tell the browser how to display content.

Basic HTML Structure

<!DOCTYPE html>
<html>
  <head>
    <title>Page Title</title>
  </head>
  <body>
    <h1>Example Heading</h1>
    <p>Example paragraph..</p>
  </body>
</html>
  • <!DOCTYPE html> — Defines the page as an HTML5 document.
  • <html> — The root element. All other elements come after this.
  • <head> — Contains information about the page (like the title).
  • <body> — Defines the HTML document's body. Only content inside the body is shown in the browser.
  • <h1> — Defines a large heading.
  • <p> — Defines a paragraph.

Tags, Attributes, and IDs

  • Tags can have attributes like class (for styling multiple elements the same way) and src (for specifying image sources: <img src="img/cat.jpg">).
  • Elements can have an id attribute (<p id="example">) which is unique to that element. Unlike class, multiple elements can't use the same id.
  • You can view the HTML of any website by right-clicking → "View Page Source".
03 — The Interactivity

JavaScript

JavaScript (JS) is one of the most popular coding languages in the world and allows pages to become interactive. HTML creates the website structure and content, while JavaScript controls the functionality of web pages. Without JavaScript, a page would not have interactive elements and would always be static.

What JS Can Do

  • Dynamically update the page in real-time without reloading
  • Change the style of a button when a particular event occurs (e.g. when a user clicks it)
  • Display moving animations
  • Interact with the user through forms, popups, and more

How JS is Loaded

  • Loaded within <script> tags directly in the page
  • Or included remotely with the src attribute: <script src="/location/of/javascript_file.js"></script>

Key JS Concepts

  • document.getElementById("demo") — Finds an HTML element on the page by its id.
  • .innerHTML = "text" — Changes the content of that element.
  • Events — HTML elements can have events like onclick or onhover that execute JavaScript when triggered.
Key Takeaway

HTML = structure. CSS = style. JavaScript = functionality. JS is executed by the browser on the client-side. This means an attacker can potentially manipulate JS on the client side — which is the foundation of many web vulnerabilities (XSS, HTML injection).

04 — First Web Vulnerability

Sensitive Data Exposure

Sensitive Data Exposure occurs when a website doesn't properly protect (or remove) sensitive clear-text information to the end-user — usually found in a site's frontend source code.

How It Happens

Websites are built using many HTML elements (tags), all of which we can see simply by "viewing the page source". A website developer may have forgotten to remove login credentials, hidden links to private parts of the website, or other sensitive data shown in HTML or JavaScript.

Real-World Example

Imagine an HTML comment left in the source code by a developer:

<!-- TODO: remove test credentials admin:password123 -->

If you viewed the page's source code and found this, you could use these credentials to log in elsewhere on the application — or worse, access backend components of the site.

Key Takeaway

Whenever you're assessing a web application for security issues, one of the first things you should do is review the page source code to see if you can find any exposed login credentials or hidden links. This is low-hanging fruit that attackers always check first.

05 — Second Web Vulnerability

HTML Injection

HTML Injection is a vulnerability that occurs when unfiltered user input is displayed on the page. If a website fails to sanitise user input (filter any "malicious" text that a user inputs into a website), and that input is used on the page, an attacker can inject HTML code into a vulnerable website.

Example: a "What's your name?" form passes the input into a JavaScript function that uses innerHTML to display it on the page. If the input isn't sanitised, you can submit HTML like <h1>Hacked</h1> or even a malicious <a href="http://hacker.com"> link — and the browser will render it as real HTML.

Why It's Dangerous

  • An attacker can control the page's appearance and functionality
  • Malicious links can trick users into clicking (phishing)
  • This is related to a more dangerous vulnerability: database injection, where user input can manipulate database queries (SQL injection)
The Golden Rule

Never trust user input. The website developer should sanitise everything the user enters before using it in the JavaScript function — in this case, removing any HTML tags. Input sanitisation is the core defense against injection vulnerabilities.

Vocabulary

Key Terms

  • Front End (Client-Side) — What the browser renders: HTML, CSS, JS. The user-facing part.
  • Back End (Server-Side) — The server processing requests: logic, databases, authentication.
  • HTML — HyperText Markup Language. Structure and content of web pages.
  • CSS — Cascading Style Sheets. Styling and appearance of web pages.
  • JavaScript (JS) — Programming language for web page interactivity and functionality.
  • Tag / Element — Building blocks of HTML (e.g. <h1>, <p>, <img>).
  • Attribute — Extra information on a tag (e.g. class, src, id).
  • Class — Attribute used to style multiple elements the same way.
  • ID — Attribute unique to a single element. Used by JS and CSS to target it.
  • View Page Source — Right-click → View Page Source to see the raw HTML.
  • innerHTML — JS property that sets or gets the HTML content of an element.
  • Events — Triggers in HTML like onclick, onhover that execute JS.
  • Sensitive Data Exposure — When a website leaves sensitive info (credentials, hidden links) visible in its source code.
  • HTML Injection — Vulnerability where unfiltered user input is rendered as HTML on the page.
  • Input Sanitisation — Filtering/cleaning user input to remove malicious code before using it.
  • SQL Injection — A related vulnerability where user input manipulates database queries (covered in later rooms).
