Your computer needs to know the server's IP address to talk to it — for this, it uses DNS. Your computer then talks to the web server using the HTTP protocol. The webserver returns HTML, JavaScript, CSS, images, etc., which your browser uses to correctly format and display the website to you.

But there are also a few other components that help the web run more efficiently and provide extra features.

02 — The Infrastructure Behind the Scenes

Other Components

Load Balancers
When a website gets a lot of traffic, one web server might no longer do the job. Load balancers receive your request first and then forward it to one of multiple servers behind it. They provide two main features: ensuring high traffic websites can handle the load and providing a failover if a server becomes unresponsive.
CDN
Content Delivery Networks host static files (JavaScript, CSS, images, videos) across thousands of servers all over the world. When a user requests a file, the CDN finds the nearest server physically located to them and serves it from there — instead of from the other side of the world.
Databases
Websites need a way to store and recall data for their users. Databases can range from a simple text file to complex clusters of multiple servers. Common databases: MySQL, MSSQL, MongoDB, Postgres. Each has its specific features.
WAF
Web Application Firewall sits between your web request and the web server. Its primary purpose is to protect the webserver from hacking or DoS attacks. It analyses requests for common attack techniques, checks if requests are from real browsers (not bots), and uses rate limiting (only allowing a certain amount of requests from an IP per second).

Load Balancer Algorithms

  • Round-robin — Sends requests to each server in turn, one after another.
  • Weighted — Checks how many requests a server is currently dealing with and sends it to the least busy server.

Health Checks

Load balancers also perform periodic health checks with each server to ensure they are running correctly. If a server doesn't respond appropriately or doesn't respond at all, the load balancer will stop sending traffic to it until it responds appropriately again.

Key Takeaway

Four components sit between you and the web server: Load Balancer (distributes traffic), CDN (speeds up static content), Database (stores data), WAF (protects against attacks). Each plays a critical role in a production web application.

03 — Inside the Server

How Web Servers Work

What is a Web Server?

A web server is software that listens for incoming connections and then utilises the HTTP protocol to deliver web content to its clients. The most common web server software: Apache, Nginx, IIS, and NodeJS.

A web server delivers files from its root directory:

  • Nginx and Apache: /var/www/html (Linux)
  • IIS: C:\inetpub\wwwroot (Windows)

Virtual Hosts

Web servers can host multiple websites with different domain names using virtual hosts. The web server checks the Host header from the HTTP request and matches it against its virtual hosts (just text-based configuration files). If a match is found, the correct website is served. If no match, the default website is served.

Virtual Hosts can have their root directory mapped to different locations. For example: one.com → /var/www/website_one, two.com → /var/www/website_two.

There's no limit to the number of different websites you can host on a web server.

Static vs Dynamic Content

Static Content
Content that never changes. Examples: pictures, JavaScript, CSS, and even HTML that never changes. These files are served directly from the webserver with no modifications.
Dynamic Content
Content that could change with different requests. Example: a blog homepage showing the latest entries, or a search page showing different results. Changes are processed on the Backend.

Everything you see in your browser is called the Frontend. The processing happening behind the scenes that you can't see is called the Backend. You can't view the websites' HTML source and see what's happening in the Backend — the HTML is the result of the Backend processing.

Scripting and Backend Languages

Backend languages make a website interactive to the user. Some examples: PHP, Python, Ruby, NodeJS, Perl and many more. These languages can interact with databases, call external services, process data from the user, and much more.

A very basic PHP example: if you requested http://example.com/index.php?name=adam

Server-side code:
<html><body>Hello <?php echo $_GET["name"]; ?></body></html>

What the client sees:
<html><body>Hello adam</body></html>

Notice: the client doesn't see any PHP code because it's processed on the Backend. This interactivity opens up security issues for web applications that haven't been created securely.

Key Takeaway

Virtual hosts = one server, multiple websites (matched by Host header). Static = files served as-is. Dynamic = content generated by backend code. The client never sees backend code — only the result. Backend processing is where most serious web vulnerabilities live.

Vocabulary

Key Terms

  • Load Balancer — Distributes traffic across multiple servers. Uses algorithms like round-robin or weighted.
  • Health Check — Periodic test by the load balancer to ensure servers are running correctly.
  • Failover — When one server goes down, traffic is redirected to a working one.
  • Round-Robin — Load balancing algorithm: sends to each server in turn.
  • Weighted — Load balancing algorithm: sends to the least busy server.
  • CDN — Content Delivery Network. Hosts static files on servers worldwide for faster delivery.
  • Database — System for storing and recalling data. Examples: MySQL, MSSQL, MongoDB, Postgres.
  • WAF — Web Application Firewall. Protects web servers from hacking and DoS attacks.
  • Rate Limiting — Restricting the number of requests from an IP per second (used by WAFs).
  • Web Server — Software that listens for connections and serves web content via HTTP. Examples: Apache, Nginx, IIS, NodeJS.
  • Root Directory — The default folder from which a web server serves files.
  • Virtual Hosts — Configuration allowing one web server to host multiple websites with different domains.
  • Host Header — HTTP header that tells the web server which website is being requested.
  • Static Content — Files that never change (images, CSS, JS). Served directly.
  • Dynamic Content — Content generated per request by backend code. Can change.
  • Frontend — What the browser displays (client-side).
  • Backend — Server-side processing. The client never sees this code, only its output.
  • Backend Languages — PHP, Python, Ruby, NodeJS, Perl — languages that process data server-side.
