01 — The Problem

Why Virtualisation?

Imagine every piece of software or every website required its own physical server. That would be incredibly expensive and inefficient. Virtualisation was created to solve exactly this problem.

Your manager asked for help improving the hardware utilization of a computer that hosts a website. This room explores the concept of virtualisation.

02 — The Old Way vs The New Way

Virtualisation Overview

Before Virtualisation

The old rule of thumb: "One server = one application." Digital services ran on physical machines, each with a single purpose (hosting a website, storing data, etc.). The problems were obvious:

  • High cost — Not just hardware, but electricity, cooling, maintenance, and data center space.
  • Low utilization — Most apps don't use the server's full capacity. Many servers sat at 5-20% usage, wasting CPU, memory, and storage.
  • Slow deployment — Setting up new physical servers could take days or weeks.
  • Hard to scale — Need more resources? Buy another physical server.

The Building Analogy

Imagine one person living alone in an entire 10-floor building. They use one floor but must maintain the entire building: electricity, cleaning, water, security. Expensive, inefficient, and wasteful.

Now imagine dividing the building into separate apartments: each has its own door, walls, kitchen, and privacy. Different people live independently. They all share the building's main structure, making it cheaper and more efficient for everyone.

  • The building = the physical server
  • The apartments = virtual machines
  • The tenants = applications or operating systems
  • The building manager = the hypervisor (the software that divides the building safely)

Each virtual computer, known as a Virtual Machine (VM), acts as an independent system with its own OS, apps, and settings, even though they all share the same physical hardware underneath.

Key Takeaway

Virtualisation enables multiple applications to share a physical server safely and efficiently. The hypervisor is the software that manages the resources for each virtual machine.

03 — The Building Blocks

Virtualisation Components

Hypervisor (The Building Manager)

The hypervisor is the core technology behind virtualisation. It's the software that creates and manages virtual machines. It:

  • Divides a physical computer into multiple virtual ones
  • Gives each VM its own share of CPU, memory, and storage
  • Keeps everything isolated and safe
  • Manages the lifecycle of VMs (start, stop, pause, clone, delete)

Type 1 vs Type 2 Hypervisors

Type 1 (Bare-Metal)
Runs directly on physical hardware. Fast, efficient, ideal for servers and professional environments (data centers, production servers, database servers).
Type 2 (Hosted)
Runs within an existing OS. Easier to install, ideal for learning, testing, and small setups (testing malware, running Kali Linux, software testing).

Virtual Machines (The Apartments)

A VM is a virtual computer created by the hypervisor. Even though it's virtual, it behaves as a real machine:

  • Has its own virtual CPU, RAM, storage, and network
  • Can run any operating system (Windows, Linux, etc.)
  • Completely isolated from other VMs — if one breaks, the others continue to work

You can deploy VMs on your own computer using tools like Oracle VirtualBox and VMware Workstation (Type 2 hypervisors).

Containers (The Rooms Inside the Apartment)

A container is a lightweight, isolated environment that runs a single application and all its dependencies. Instead of bringing a whole separate OS, a container borrows the kernel of the host system.

  • They package the application and its dependencies (libraries, tools, versions)
  • They share the host's OS kernel, so they start almost instantly
  • They remain isolated from each other — a misbehaving container doesn't affect others
  • They run consistently on any machine — perfect for development, testing, and scalable deployments

The easiest way to deploy containers is using Docker — an open-source platform for building, deploying, and running applications using containerization.

Important limitation: containers share the host's kernel, so they must match the host system's type. You can't run a Windows container on a Linux machine.

VM vs Container — Key Difference

VMs = full apartments with maximum separation and flexibility (own OS, own everything). Containers = rooms inside apartments — lightweight, fast to deploy, share the kernel, ideal for scalable applications.

04 — Hands-On

Managing Virtual Machines

This task simulates managing VMs in a professional environment at AutoCloud, a company that has recently started using virtual machines.

VM States

  • Summary — General view of the state of the environment.
  • Virtual Machines — Details of VMs (start, stop, actions).
  • Node — Displays usage and performance details for each physical server.

Key Actions

  • Analyze VM states — Check if VMs are running, stopped, or in error. Restart errored VMs.
  • Create new VMs — Choose name, instance type (size), and launch.
  • Analyze hardware usage — Check physical server utilization (CPU, memory). Identify which servers are overloaded and which have capacity.

Reading Hardware Utilization

  • cn-runlab-01 at 40% CPU, 65% memory → Still has capacity to host more VMs
  • cn-PROD-01 at 100% CPU → Already at maximum, might need to rebalance
  • cn-backup-01 at 0% → The server is not running
Key Takeaway

Managing VMs in production means monitoring states, creating resources on demand, and keeping an eye on hardware utilization. Over-provisioning wastes money, under-provisioning causes outages. It's a balancing act.

05 — Recap

Key Terminology

  • Virtualization — Enables a single physical computer to act like multiple separate computers.
  • Hypervisor — The "manager" software that makes and runs the virtual computers.
  • Virtual Machine (VM) — A whole virtual computer inside the real one, with its own system.
  • Container — A small, isolated box for one app that shares the same system as the host.
  • Container Image — A pre-packed recipe/template used to create containers.
  • Network Ports — Special numbered entry points that apps use to talk over the network.

Key Benefits of Virtualisation

  • Cost savings
  • Better resource usage
  • Safe testing for cyber security
  • Faster deployment
  • Flexibility
  • Portability
  • Scalability
  • Centralized management
Vocabulary

Key Terms

  • Virtualisation — Running multiple virtual computers on a single physical machine.
  • Hypervisor — Software that creates and manages VMs. The "building manager".
  • Type 1 (Bare-Metal) — Hypervisor running directly on hardware. For production/data centers.
  • Type 2 (Hosted) — Hypervisor running within an existing OS. For learning/testing.
  • VM (Virtual Machine) — A full virtual computer with its own OS, CPU, RAM, storage.
  • Container — Lightweight isolated environment sharing the host's kernel. Fast to start.
  • Docker — Open-source platform for building and running containers.
  • Container Image — Template/recipe used to create containers.
  • Kernel — The core of an OS that communicates with hardware and manages resources.
  • VirtualBox — Free Type 2 hypervisor by Oracle.
  • VMware Workstation — Commercial Type 2 hypervisor.
  • Host — The physical machine running the hypervisor.
  • Guest — The virtual machine running on the host.
  • Isolation — VMs and containers are separated from each other for safety.
