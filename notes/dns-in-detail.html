01 — The Phone Book of the Internet

What is DNS?

DNS (Domain Name System) provides a simple way for us to communicate with devices on the Internet without remembering complex numbers.

Much like every house has a unique address for sending mail, every computer on the Internet has its own unique address to communicate with — an IP address (e.g. 104.26.10.229). Remembering that for every website isn't convenient, so DNS lets you remember tryhackme.com instead.

Key Takeaway

DNS = translates domain names into IP addresses. It's like a phone book: you look up a name, you get the number. Without DNS, you'd need to memorize the IP address of every website you visit.

TLD — Top-Level Domain

The most righthand part of a domain name. For example, the TLD of tryhackme.com is .com. There are two types:

  • gTLD (Generic Top Level) — Originally meant to tell the user the domain's purpose: .com for commercial, .org for organisation, .edu for education. Due to high demand, there's now an influx of new gTLDs: .online, .club, .website, .biz, and many more (over 2000 TLDs).
  • ccTLD (Country Code Top Level) — Used for geographical purposes: .ca for Canada, .co.uk for the United Kingdom, .fr for France.

Second-Level Domain

Taking tryhackme.com as an example, the .com part is the TLD, and tryhackme is the Second-Level Domain. When registering a domain name, the second-level domain is limited to 63 characters and can only use a-z, 0-9, and hyphens (cannot start or end with hyphens or have consecutive hyphens).

Subdomain

A subdomain sits on the left-hand side of the Second-Level Domain, separated by a period. For example, in admin.tryhackme.com, the admin part is the subdomain.

  • Same creation restrictions as the Second-Level Domain (63 chars, a-z 0-9 hyphens)
  • You can use multiple subdomains split with periods: jupiter.servers.tryhackme.com
  • But the total length must be kept to 253 characters or less
  • There is no limit to the number of subdomains you can create
Key Takeaway

Domain structure from right to left: Root → TLD → Second-Level Domain → Subdomain. For admin.tryhackme.com: TLD = .com, SLD = tryhackme, Subdomain = admin. Max subdomain length = 63 chars, max total = 253 chars.

03 — Types of DNS Records

DNS Record Types

DNS isn't just for websites — multiple types of DNS records exist. Here are the most common ones:

A Record
Resolves to IPv4 addresses. Example: 104.26.10.229
AAAA Record
Resolves to IPv6 addresses. Example: 2606:4700:20::681a:be5
CNAME Record
Resolves to another domain name. Example: store.tryhackme.com → CNAME → shops.shopify.com. A second DNS request is then made to resolve that domain's IP.
MX Record
Resolves to the address of the servers that handle email for the domain. Comes with a priority flag — tells the client which order to try the servers (backup if main goes down).

TXT Record

TXT records are free text fields where any text-based data can be stored. Common uses:

  • List servers that have authority to send email on behalf of the domain (helps fight spam and spoofed email)
  • Verify ownership of the domain name when signing up for third-party services
Key Takeaway

Memorize 5 record types: A (IPv4), AAAA (IPv6), CNAME (alias to another domain), MX (email servers), TXT (free text / verification). The MX record is what tells the Internet where to send email for a domain.

  • Step 1 — Local Cache — Your computer first checks its local cache to see if you've previously looked up the address recently. If not, a request goes to your Recursive DNS Server.
  • Step 2 — Recursive DNS Server — Usually provided by your ISP (but you can choose your own, e.g. Google 8.8.8.8). This server also has a local cache of recently looked-up domain names. If a result is found locally (common for popular services like Google, Facebook), your request ends here.
  • Step 3 — Root DNS Servers — The backbone of DNS. Their job is to redirect you to the correct Top Level Domain server. For example, if you request www.tryhackme.com, the root server recognises the .com TLD and refers you to the correct TLD server.
  • Step 4 — TLD Server — Holds records for where to find the authoritative server to answer the DNS request. The authoritative server is often also known as the nameserver for the domain.
  • Step 5 — Authoritative DNS Server — The server responsible for storing the DNS records for a particular domain name and where any updates to your domain name DNS records would be made. Depending on the record type, the DNS record is then sent back to the Recursive DNS Server, where a local copy is cached for future requests. The result is then relayed back to the original client.

TTL — Time to Live

DNS records all come with a TTL (Time To Live) value — a number represented in seconds that the response should be saved for locally until you have to look it up again. Caching saves on having to make a DNS request every time you communicate with a server.

Key Takeaway

The DNS journey: Local Cache → Recursive DNS (ISP) → Root Server → TLD Server → Authoritative Server. Most requests never go past step 2 because popular domains are cached. The TTL determines how long a cached record stays valid. The Recursive DNS Server is usually provided by your ISP. The Authoritative Server holds all the actual records for a domain.

Vocabulary

Key Terms

  • DNS — Domain Name System. Translates domain names to IP addresses.
  • Domain Name — Human-readable website address (e.g. tryhackme.com).
  • TLD — Top-Level Domain. The rightmost part (.com, .org, .fr).
  • gTLD — Generic Top-Level Domain (.com, .org, .biz).
  • ccTLD — Country Code Top-Level Domain (.uk, .ca, .fr).
  • Second-Level Domain (SLD) — The name you register (tryhackme in tryhackme.com). Max 63 chars.
  • Subdomain — Left of the SLD (admin in admin.tryhackme.com). Max 63 chars each, total max 253.
  • A Record — Maps domain to IPv4 address.
  • AAAA Record — Maps domain to IPv6 address.
  • CNAME Record — Maps domain to another domain name (alias).
  • MX Record — Points to email servers for the domain. Has a priority flag.
  • TXT Record — Free text field. Used for email authentication and domain verification.
  • Recursive DNS Server — Usually your ISP's DNS. First external stop. Caches results.
  • Root DNS Server — The backbone. Redirects to the correct TLD server.
  • TLD Server — Knows where the authoritative server is for that TLD.
  • Authoritative DNS Server — The final authority. Holds all DNS records for a domain. Also called the nameserver.
  • TTL — Time to Live. How long (in seconds) a DNS record is cached before re-querying.
  • Cache — Local storage of previously looked-up DNS records for faster access.
