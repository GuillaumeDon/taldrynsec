02 — How an OS Works

The Invisible Manager

An operating system (OS) is the core software that coordinates everything happening on a computer. It sits between the user, applications, and the system's physical hardware, acting as the invisible manager that keeps the entire machine running as one unified system.

The Airport Analogy

  • Your hardware (CPU, RAM, storage) = the runways, airplanes, fuel systems, radar, and other physical infrastructure
  • Your applications (web browser, game launcher) = the airlines and their passengers, all trying to take off, land, and request services
  • Your operating system (Windows, Linux, macOS) = the air traffic control system, directing all activity. It schedules resources, manages traffic, resolves conflicts, and ensures safety.

Without an OS, each application would need direct control over the CPU, memory, files, devices, and security. This would quickly cause conflicts — the OS handles this by acting as the central organiser.

System Privilege Layers

  • Kernel space — The privileged, locked-down core of the OS. This is the kernel itself: it directly manages hardware and system resources. It has unrestricted access to CPU, memory, storage, and all hardware components.
  • User space — Where all standard applications run. Applications here are deliberately prevented from accessing hardware directly. When they need to open a file, play a sound, or connect to Wi-Fi, they must make a system call and request the kernel to act on their behalf.

In the airport analogy: the kernel is the control tower — a strictly secured area where only trusted air traffic controllers work. Applications in user space are like airlines on the ground. They can't enter the tower directly. Instead, they radio requests (system calls) to the tower, which handles them safely.

OS Core Duties

Process Management
Creates, schedules, prioritizes, and terminates programs. Decides how much CPU time each process gets — makes multitasking feel seamless.
Memory Management
Allocates RAM to processes, protects each app's memory from other processes, and reclaims memory when apps are closed. Uses virtual memory when RAM runs low.
File System Management
Organizes files into directories, handles naming, paths, permissions, metadata (name, size, type, timestamps).
User Management
Handles multiple user accounts, authentication, and permissions to determine who can access what.
Device Management
Loads drivers and provides a universal interface (hardware abstraction layer), so apps can say "print this" without knowing the specific printer model.

Operating System Security

Every OS also acts as a security foundation. Before any antivirus, firewall, or security tool is introduced, the OS is already enforcing protections in the background:

  • Authentication — Verifies who you are through login passwords and biometrics.
  • Permissions — Controls exactly what each user and app is allowed to read, write, or execute.
  • Isolation — Keeps every process in its own protected box (kernel/user space separation).
  • System Protection — Safeguards critical system files and settings from unauthorized changes.
Key Takeaway

The OS is the invisible manager between you and the hardware. Kernel space = control tower (full access, restricted). User space = ground (limited, must ask permission via system calls). Understanding this separation is crucial for cybersecurity.

03 — Types & Interfaces

OS Interaction and Landscape

GUI vs CLI

GUI — Graphical User Interface

The visual part of the OS: windows, icons, menus. What you're most used to. Like using a navigation app — tap an icon, the app generates directions. Easy but less precise.

CLI — Command-Line Interface

Text-based: you type specific commands to control the system. Like entering the exact GPS coordinates of your destination. More precise, faster, more control — but requires knowing the commands.

Both GUI and CLI retrieve the same information — they're just different ways to interact. The GUI needs a few clicks for folder navigation; the CLI requires one command to list directory contents.

Real-World Operating Systems

Desktop

  • Windows — Most widely used desktop OS. Versions: Windows 10 (end of life), Windows 11.
  • macOS — Apple's desktop OS, known for polished GUI and integration with Apple devices. Versions: Sequoia, Sonoma.
  • Linux — Not a single OS but a family of open-source systems called distributions. Examples: Ubuntu, Debian, Fedora.

Server

  • Windows Server — Used in corporate environments. Versions: 2016, 2019, 2022, 2025.
  • Linux — The vast majority of web servers. Distributions: Ubuntu Server, Debian, CentOS, Red Hat.
  • Unix — Large enterprises, finance, telecom, government. Examples: IBM AIX, Oracle Solaris.

Mobile

  • Android — Most widely used mobile OS. Runs on phones, tablets, smart devices.
  • iOS — Apple's mobile OS for iPhones and iPads.

Embedded & IoT

  • Embedded Linux — Specialized OS built into devices. Examples: OpenWrt, Ubuntu Core, Yocto Project.
  • Real-Time OS — For apps needing guaranteed response times (aircraft controls). Examples: FreeRTOS, VxWorks, QNX.

Virtual & Cloud

  • Cloud/VM — Massive data centers hosting websites, apps, streaming. Examples: Ubuntu LTS, Amazon Linux, Rocky Linux.
  • Container-optimized — Lightweight alternatives to VMs. Examples: Alpine Linux, Bottlerocket AWS, Flatcar Linux.

Why So Many Operating Systems?

Different devices require different capabilities. A laptop must be user-friendly; servers need stability and uptime; mobile devices need power efficiency; embedded systems use lightweight OS designed for a specialized purpose. No single OS is the perfect fit for every situation.

Key Takeaway

GUI = visual, easy, like using a nav app. CLI = text commands, precise, like entering GPS coordinates. Both access the same system — different interfaces, same power. And there are 5 major categories of OS: Desktop, Server, Mobile, Embedded, Virtual/Cloud.

04 — Recap

Key Terminology

  • Operating System (OS) — The core software that manages hardware, applications, and all system resources.
  • Kernel space — The OS's highly privileged area with direct hardware access, home of the kernel which directly manages hardware and system resources.
  • User space — The area where regular applications run with limited permissions for safety and system stability.
  • GUI — Graphical User Interface. The visual part: windows, icons, menus. Interact through clicking and tapping.
  • CLI — Command-Line Interface. A text-based interface where you type commands to control the system with precision and speed.

Vocabulary

Key Terms

  • Operating System (OS) — Core software managing hardware, apps, and system resources.
  • Kernel — The core of the OS with unrestricted hardware access.
  • Kernel Space — Privileged area where the kernel runs. Like the control tower.
  • User Space — Restricted area where applications run. Like the ground level.
  • System Call — How apps in user space request services from the kernel.
  • Process Management — OS duty: scheduling, prioritizing, and terminating programs.
  • Memory Management — OS duty: allocating and protecting RAM for each process.
  • Virtual Memory — Using disk space as extra RAM when physical RAM is full.
  • File System Management — OS duty: organizing files, directories, permissions.
  • User Management — OS duty: handling accounts, authentication, permissions.
  • Device Management — OS duty: loading drivers, providing hardware abstraction.
  • Driver — Software that lets the OS communicate with a specific hardware device.
  • GUI — Graphical User Interface. Visual interaction (click, tap).
  • CLI — Command-Line Interface. Text-based interaction (type commands).
  • Authentication — Verifying user identity (passwords, biometrics).
  • Permissions — Rules controlling what users/apps can read, write, or execute.
  • Isolation — Keeping processes separated for security (kernel/user space).
  • Distribution (distro) — A specific version/flavor of Linux (Ubuntu, Debian, Fedora).
  • Real-Time OS — OS guaranteeing response times for critical systems.
