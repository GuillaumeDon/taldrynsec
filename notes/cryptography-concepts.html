01 — Introduction

Why Cryptography Matters

The padlock in your browser's address bar — what's actually stopping someone from reading your data as it travels across the internet? That's cryptography.

Data doesn't travel directly from you to the recipient. It bounces through dozens of computers and routers. Without protection, anyone with access to those systems could read, change, or block your data — attacking all three pillars of the CIA Triad.

Cryptography solves this by using mathematical rules and secret keys to scramble information into gibberish that only authorised people can unscramble.

Core Vocabulary

  • Plaintext — A message you can read normally. Example: HELLO
  • Ciphertext — A scrambled version not supposed to make sense. Example: KHOOR
  • Key — The secret that controls how scrambling and unscrambling works. Only people with the right key can decrypt.
  • Algorithm — The public recipe (the steps) that says how to use the key on the message. Everyone can know the algorithm — security comes from keeping the key secret.

Decryption is the reverse: Ciphertext + Key + Algorithm → Plaintext.

Key Takeaway

The algorithm is public — the key is the only secret. Security does not come from hiding how encryption works, but from protecting the key. This is Kerckhoffs's principle.

02 — Symmetric Encryption

One Key for Both Directions

Symmetric encryption uses the same key to both encrypt and decrypt. Alice and Bob both know this secret key. Alice encrypts with it, Bob decrypts with it.

🔒

The Lockbox Analogy

Alice puts her message in a lockbox and locks it. She mails the lockbox to Bob. Bob uses his copy of the same key to open it. Anyone who intercepts the box along the way can't open it — but only if they don't have the key.

⚡

Why It's Used

Symmetric algorithms are very fast. They can encrypt large amounts of data quickly — perfect for encrypting files, hard drives, and high-speed network traffic.

The Caesar Cipher — Algorithm + Key in Action

The Caesar cipher shifts each letter in the alphabet by a fixed number. That number is the key. The shift rule is the algorithm. It's historically famous but completely insecure — used here only to illustrate the concept.

Example: key = 3 (shift forward 3)

H→ +3 →K
E→ +3 →H
L→ +3 →O
L→ +3 →O
O→ +3 →R (wraps around at Z)
HELLO → encrypted with key=3 → KHOOR
To decrypt: shift backwards by 3. KHOOR → HELLO.

Why the Caesar cipher is weak: the algorithm is completely public, and there are only 25 possible key values (1–25). A computer checks all 25 in milliseconds — this is called a brute-force attack. Real symmetric algorithms (AES, ChaCha20) use keys that are billions of years to brute-force.

The Key Distribution Problem

Symmetric encryption has one critical weakness: how do Alice and Bob share the key safely in the first place? If they send it in plaintext, an attacker intercepts it. If they encrypt it, they need another key — circular problem. This is the key distribution problem, and it's why asymmetric encryption was invented.

Key Takeaway

Symmetric = one key, both directions. Fast, efficient. Algorithm + key → ciphertext. Key distribution is the weakness. Real-world algorithms: AES, DES, ChaCha20.

03 — Asymmetric Encryption

Two Keys Instead of One

Asymmetric encryption uses two mathematically linked keys:

  • Public key — Anyone can know it and use it. Used to encrypt.
  • Private key — Only one person keeps it, secret. Used to decrypt.

If you encrypt something with someone's public key, only their private key can decrypt it. This solves the key distribution problem — you can share your public key with the entire world safely.

📬

The Mailbox Analogy

The mail slot is the public key — anyone can drop a letter in. It's completely open and accessible. The locked door is the private key — only the mailbox owner has the key to open it and grab the letters.

🐢

The Tradeoff

Asymmetric encryption is much slower than symmetric. It's used for small amounts of data — primarily to securely exchange a symmetric key, after which symmetric encryption takes over for the bulk of the data.

Asymmetric Flow — Alice sends to Bob

1Bob creates a public key and a private key. He keeps the private key secret and shares the public key with the world.
2Alice finds Bob's public key (on a website, or he sends it openly).
3Alice encrypts her message using Bob's public key and sends it.
4Bob decrypts with his private key — he is the only one who can, because no one else has it.
✓An attacker who intercepts the message cannot decrypt it without Bob's private key.

Real-World Use: HTTPS

The padlock in your browser = HTTPS. This is how the two encryption types combine in practice:

1Your browser requests the website. The server sends its public key inside a certificate.
2Your browser checks the certificate is signed by a trusted Certificate Authority (CA).
3Asymmetric encryption is used to securely agree on a shared symmetric session key.
4From this point, all data is encrypted with symmetric encryption (fast) using that session key.

Asymmetric solves the key distribution problem. Symmetric handles the heavy lifting efficiently. HTTPS uses both.

Vocabulary

Key Terms

  • Cryptography — The science of securing communication using mathematical techniques to make data unreadable to unauthorised parties.
  • Plaintext — The original readable message before encryption.
  • Ciphertext — The scrambled, unreadable output after encryption.
  • Key — The secret value that controls encryption and decryption. The algorithm is public — the key is the only secret.
  • Algorithm — The public set of mathematical steps that uses the key to encrypt or decrypt data.
  • Symmetric Encryption — One key used for both encryption and decryption. Fast. Examples: AES, ChaCha20.
  • Asymmetric Encryption — Two linked keys: a public key (anyone can use) and a private key (only the owner has). Examples: RSA, ECC.
  • Public Key — The shareable key in asymmetric encryption. Used to encrypt messages to the owner.
  • Private Key — The secret key in asymmetric encryption. Only the owner has it. Used to decrypt.
  • Key Distribution Problem — The challenge of securely sharing a symmetric key. Solved by asymmetric encryption.
  • Caesar Cipher — A simple substitution cipher that shifts letters by a fixed number. Historically significant, but trivially brute-forced.
  • Brute-Force Attack — Trying all possible keys systematically until the correct one is found.
  • HTTPS — HyperText Transfer Protocol Secure. Uses asymmetric encryption for the handshake, then symmetric for the session data.
  • Certificate — A digital document containing a website's public key, signed by a trusted Certificate Authority (CA). Proves the public key belongs to the legitimate site.
  • Certificate Authority (CA) — A trusted organisation that signs and validates digital certificates.
  • Session Key — A temporary symmetric key generated for one communication session. Agreed upon via asymmetric encryption.
  • Kerckhoffs's Principle — A cryptographic system should be secure even if everything except the key is public knowledge.

What is the difference between plaintext and ciphertext?
Plaintext is the original readable message. Ciphertext is the scrambled, unreadable version produced by encryption.
What is a key in cryptography? What is an algorithm?
A key is the secret value that controls encryption/decryption. An algorithm is the public set of steps (the recipe) for using the key. The algorithm can be known by everyone — only the key must stay secret.
What is symmetric encryption? Give a real-world analogy.
Encryption where the same key is used for both encryption and decryption. Analogy: a lockbox — Alice and Bob both have a copy of the same key to lock and unlock it.
What is the key distribution problem?
The challenge of securely sharing a symmetric key with another party. If you send it in plaintext, it can be intercepted. If you encrypt it, you need another key — circular problem.
What is asymmetric encryption? How many keys does it use?
Encryption using two mathematically linked keys: a public key (anyone can use to encrypt) and a private key (only the owner has to decrypt). Two keys total.
In asymmetric encryption, which key encrypts? Which decrypts?
The public key encrypts (anyone can send a secret message to the owner). The private key decrypts (only the owner can read it).
What is the mailbox analogy for asymmetric encryption?
The mail slot = public key (anyone can drop a letter in). The locked door = private key (only the mailbox owner has the key to retrieve letters).
Why is asymmetric encryption not used to encrypt all data?
It is much slower than symmetric encryption. It is only used for small amounts of data — primarily to securely exchange a symmetric session key.
How does the Caesar cipher work? What is its key?
It shifts each letter in the alphabet by a fixed number. That number is the key. Example: key=3, HELLO → KHOOR. To decrypt: shift backwards by 3.
Why is the Caesar cipher insecure?
There are only 25 possible keys (1–25). A computer can try all of them in milliseconds — this is a brute-force attack.
How does HTTPS combine both encryption types?
Asymmetric encryption is used during the handshake to securely agree on a shared symmetric session key. Then symmetric encryption handles all the actual data (faster).
What is a digital certificate? What does it contain?
A digital document containing a website's public key, signed by a Certificate Authority (CA). It proves the public key genuinely belongs to that website and not an attacker.
What is a Certificate Authority (CA)?
A trusted organisation that signs and validates digital certificates. Your browser and OS come with a list of trusted CAs. If a certificate is signed by one, it's trusted.
Which CIA pillars does cryptography protect?
Confidentiality (encryption prevents unauthorised reading) and Integrity (digital signatures detect tampering). It does not directly protect Availability.
What is Kerckhoffs's principle?
A cryptographic system should remain secure even if everything about the system — except the key — is public knowledge. Security comes from the key, not from hiding the algorithm.
