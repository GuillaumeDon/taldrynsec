01 — The Big Picture

What is Defensive Security?

Offensive security is about breaking in. Defensive security is the opposite — it's about preventing intrusions from happening and detecting & responding to them when they do. Blue teams specialize in this.

Core Tasks of Defensive Security

  • User cyber security awareness — Training users to recognize threats targeting their systems (phishing, social engineering…).
  • Documenting and managing assets — You can't protect what you don't know exists. Know your systems and devices.
  • Updating and patching — Keep computers, servers, and network devices patched against known vulnerabilities.
  • Preventative security devices — Set up firewalls (control what traffic goes in/out) and IPS (Intrusion Prevention Systems — block traffic matching attack signatures).
  • Logging and monitoring — Proper network logging is essential to detect malicious activity and unauthorized devices.
Key Takeaway

Defensive security has two main goals: 1) prevent intrusions and 2) detect and respond when they happen. Everything else branches from these two.

02 — Key Area

Security Operations Center (SOC)

A team of cybersecurity professionals that monitors the network and its systems 24/7 to detect malicious cyber security events.

What a SOC Watches For

  • Vulnerabilities — Discovered when a system isn't updated. Must be fixed by installing the proper patch. Not always assigned to the SOC, but the SOC needs to know about them.
  • Policy violations — Actions that break security rules. Example: uploading confidential company data to an online storage service.
  • Unauthorized activity — Stolen login credentials used to access the network. The SOC must detect and block this.
  • Network intrusions — An attacker gaining access to the network. The goal: detect and respond as fast as possible to limit damage.
Key Takeaway

The SOC relies on a SIEM (Security Information and Event Management) — a tool that collects and aggregates logs from multiple sources across the network and uses rules to detect suspicious activity and trigger alerts.

03 — Key Area

Threat Intelligence

Intelligence about actual and potential adversaries. The purpose: help the company achieve a threat-informed defense.

How it Works

Different adversaries have different motives: some want to steal data via a mobile operator, some want to halt production (refineries), some are nation-state cyber armies or ransomware groups acting for financial gain.

  • Collect — Data from network logs, public sources (forums, dark web…).
  • Process — Organize raw data into a format suitable for analysis.
  • Analyze — Identify the threat actor (adversary), their motives, and predict their actions.
  • Recommend — Create actionable recommendations and a response strategy.
Key Takeaway

Learning the adversary's TTPs (Tactics, Techniques, and Procedures) lets you anticipate attacks instead of just reacting. Based on the company's threat landscape, you can expect certain types of adversaries.

04 — Key Area

Digital Forensics & Incident Response (DFIR)

Digital Forensics

The application of science to investigate digital evidence — crimes, attacks, IP theft, cyber espionage, or unauthorized content.

  • File System — Analyze a low-level copy (image) of a system's storage. Reveals installed programs, created files, partially overwritten files, and deleted files.
  • System Memory (RAM) — If the malware runs only in memory without saving to disk, you need a forensic image of the RAM to analyze it.
  • System Logs — Each client and server maintains different log files about what happened on the system. Even if the attacker clears their traces, some logs will remain.
  • Network Logs — Logs of network packets that have traversed a network help answer whether an attack is occurring and what it entails.

Incident Response

A data breach or cyber attack can be anything: misconfiguration, intrusion attempt, policy violation, defacing a public website, or a data breach leaking company data. You need a methodology to handle it and reduce damage in the shortest time possible.

Activity
  • Preparation — Train the team, put measures in place to prevent incidents in the first place.
  • Detection & Analysis — Have the resources to detect any incident. When detected, analyze severity and source.
  • Containment, Eradication & Recovery — Stop the incident from spreading (e.g. isolate a virus-infected system), eliminate the threat, and recover affected systems.
  • Post-Incident Activity — After successful recovery, produce a report and share lessons learned to prevent similar incidents in the future.
Key Takeaway

It's a cycle, not a line: lessons learned in phase 4 feed back into better preparation in phase 1. Each incident makes your defenses stronger.

05 — Key Area

Malware Analysis

Malware = malicious software. Includes programs, documents, and files you can save on a disk or send over the network.

Types of Malware

Virus
A piece of code that attaches itself to a program. Designed to spread from one computer to another by altering, overwriting, and deleting files.
Trojan Horse
A program that looks like a desirable function but hides a malicious function underneath. Example: a victim downloads a video player from a shady website that gives the attacker control over their system.
Ransomware
Encrypts the user's files and makes them unreadable without the decryption password. The attacker offers the password in exchange for payment ("ransom").

Analysis Methods

  • Static analysis — Inspect the malicious program without running it. Requires solid knowledge of assembly language (the processor's instruction set).
  • Dynamic analysis — Run the malware in a controlled environment (sandbox) and monitor its activities. Lets you observe how it actually behaves when running.
Key Takeaway

Static = look at the code without executing. Dynamic = execute and observe. Both are complementary — static tells you what the code can do, dynamic tells you what it does do.

06 — In Practice

A Day as a SOC Analyst

The room gives a practical scenario: you're a SOC analyst at a bank. Your SIEM collects security-related information from various sources and presents them in one dashboard. When something looks suspicious, an alert is generated.

Types of Alerts You Might See

  • Executed binary file — Someone ran a suspicious file (e.g. image.jpg.exe — double extension trick).
  • Failed login attempts — A user with 5+ failed logins could mean brute force or a forgotten password.
  • Login at unusual time — Someone logging in at 3AM when they normally work 9-5.
  • Login from new location — An account accessed from an unexpected IP or country.

The Analyst's Job

Not all alerts are malicious. The analyst uses their expertise to investigate and determine which ones are real threats and which are false positives. Examples:

  • Failed logins might just be a user who forgot their password.
  • Connections from unknown IPs could mean someone new is trying to connect — or unauthorized access.
Key Takeaway

A SIEM generates alerts, but it takes a human analyst to triage them — distinguish real threats from noise, investigate context, and decide on the appropriate response. Judgment is what separates a good SOC analyst from an alert feed.

Vocabulary

Key Terms to Remember

  • SOC — Security Operations Center: team monitoring for malicious events.
  • SIEM — Security Information and Event Management: tool aggregating logs & generating alerts.
  • IPS — Intrusion Prevention System: blocks traffic matching known attack signatures.
  • Firewall — Controls what network traffic can enter and leave a network.
  • DFIR — Digital Forensics and Incident Response.
  • TTPs — Tactics, Techniques, and Procedures of an adversary.
  • Threat Actor — The adversary (person or group) behind an attack.
  • Sandbox — Controlled environment to safely run and analyze malware.
  • Blue Team — The defensive security team (as opposed to Red Team = offensive).
