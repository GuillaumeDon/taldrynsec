Search Skills

Evaluate sources, master search operators, use specialized engines (Shodan, Censys, VirusTotal), and read technical documentation.

Blue Team Cyber Security 101 Beginner
01 — Evaluation of Search Results

Not All Information Is Equal

Everyone can publish on the internet — blog posts, articles, social media, wiki edits. This means anyone can voice unfounded claims. As a security professional, you must evaluate information critically before trusting it.

Source
Identify the author or organisation publishing the information. Are they reputable and authoritative on the subject? A blog post does not make someone an authority.
Evidence & Reasoning
Are the claims backed by credible evidence and logical reasoning? Seek hard facts and solid arguments, not opinion or speculation.
Objectivity & Bias
Is the information presented impartially and rationally? Watch for hidden agendas — promoting a product, attacking a rival, or pushing an ideology.
Corroboration & Consistency
Validate by checking multiple independent, reputable sources. Do they all agree on the central claims? Consistency across sources increases credibility.
Key Takeaway

In cybersecurity, acting on bad intelligence can be dangerous. Always apply the 4-point check: Source → Evidence → Objectivity → Corroboration. Never trust a single source for a critical claim.

02 — Search Engine Operators

Harnessing the Full Power of Google

Most people use search engines passively. Security professionals use advanced operators to search with surgical precision — filtering by site, file type, exact phrase, or excluding unwanted results.

"exact phrase"
"passive reconnaissance"

Double quotes force the search engine to return only pages containing that exact word or phrase in that exact order.

site:
site:tryhackme.com success stories

Limits results to a specific domain. Useful for searching within a known trusted source or scoping recon to one target.

-keyword
pyramids -tourism

The minus sign excludes results containing that word. Filters out irrelevant noise when a topic has multiple meanings.

filetype:
filetype:pdf cyber warfare report

Finds specific file types — PDF, DOC, XLS, PPT. Essential for finding official reports, whitepapers, and leaked documents.

Key Takeaway

Combining operators is powerful: site:gov filetype:pdf "incident response" returns only government PDF documents about incident response. This is the foundation of Google Dorking — using search engines as an OSINT tool.

03 — Specialized Search Engines

OSINT Tools Beyond Google

Standard search engines index web pages. Specialized engines index internet-connected devices, certificates, files, malware, and breached data — resources that Google doesn't surface.

🔴 Shodan

shodan.io

Search engine for internet-connected devices — servers, routers, webcams, industrial control systems, IoT. Find specific software versions, open ports, and exposed services worldwide. Example: search apache 2.4.1 to find all servers running that version.

🔵 Censys

censys.io

Similar to Shodan but focuses on internet-connected hosts, websites, and certificates. Good for enumerating domains in use, auditing open ports, and discovering misconfigurations in a network.

🟢 VirusTotal

virustotal.com

Online malware scanner that checks files or URLs against 60+ antivirus engines simultaneously. Input file hashes to check previously uploaded files. Community comments provide deeper context when AV flags are ambiguous.

🩷 Have I Been Pwned

haveibeenpwned.com

Tells you if an email address appeared in a known data breach. Leaked credentials often include usernames, passwords, and account details. Passwords in breaches are often encrypted but many can be recovered — reuse is dangerous.

Key Takeaway

These tools are essential for OSINT and recon. Shodan/Censys expose attack surface. VirusTotal validates suspicious files. HIBP checks credential exposure. All are used by both attackers and defenders — know them from both sides.

04 — Vulnerabilities & Exploits

CVE + Exploit Database

The CVE (Common Vulnerabilities and Exposures) program is a dictionary of known vulnerabilities. Every vulnerability gets a unique CVE ID in the format CVE-YEAR-NUMBER (e.g. CVE-2014-0160 = Heartbleed). This ensures all security researchers, vendors, and tools refer to the same vulnerability using the same identifier.

  • MITRE maintains the CVE system → cve.mitre.org
  • NVD (National Vulnerability Database) → enriched CVE data with CVSS scores → nvd.nist.gov
  • Exploit Database → exploit-db.com — lists verified exploit code for known CVEs
  • GitHub → search any CVE ID to find PoC (Proof of Concept) code and tools contributed by the community
Key Takeaway

When you hear about a vulnerability, look it up by CVE ID. NVD gives the severity (CVSS score). Exploit-DB shows whether public exploit code exists. GitHub shows PoC tools. This workflow is used daily by both defenders (patching decisions) and pentesters (exploit selection).

05 — Technical Documentation

Reading Official Docs

Official documentation is always the most accurate and up-to-date source for how a product or command works. Get comfortable finding and reading it.

🐧

Linux man pages

Run man <command> in terminal. Also searchable online: type "man ip" in Google to find the web version.

🪟

Microsoft Docs

Official documentation for all Windows commands and products at learn.microsoft.com.

📦

Product Docs

Every major product has official docs: Apache, PHP, Node.js, Snort, etc. Always prefer these over blog posts.

Key Takeaway

When in doubt, RTFM (Read The Fine Manual). Official documentation is authoritative, free, and always more accurate than Stack Overflow or blog posts. Build the habit: unknown command → man <command> first.

06 — Social Media & News

Social Media as an OSINT Tool

Social media platforms (LinkedIn, Twitter/X, Facebook) are powerful for OSINT — both for staying updated on cybersecurity trends and for gathering information about targets.

For Defenders — Threat Intelligence

  • Follow security researchers, vendors, and CERTs for real-time threat updates
  • LinkedIn reveals employee roles, tech stack, and infrastructure clues
  • Twitter/X surfaces breaking CVEs and PoC disclosures within hours

For Red Teamers — OSINT on Targets

  • LinkedIn profiles reveal an employee's technical background — which tools, languages, and systems they use
  • Social media can expose answers to secret questions (school name, pet name, mother's maiden name) — used in account takeover attacks
  • People often overshare information that helps attackers build a spear-phishing profile

Operational Security (OPSEC) Warning

If you need to explore a platform for research, use a temporary account with a throwaway email — not your real identity. Don't link reconnaissance activity back to your primary persona.

Key Takeaway

Social media is a double-edged OSINT sword. As a defender: follow security channels to stay current. As a red teamer: LinkedIn reveals the technical profile of employees. Overshared personal details = secret question answers = account takeover vector.

Vocabulary

Key Terms

  • OSINT — Open Source Intelligence. Gathering information from publicly available sources.
  • Search Operator — A special syntax added to a search query to refine results (e.g. site:, filetype:, "quotes", -exclude).
  • Google Dorking — Using advanced Google search operators to find sensitive information exposed on the web.
  • Shodan — Search engine for internet-connected devices. Reveals open ports, running services, and software versions.
  • Censys — Similar to Shodan; focuses on internet-connected hosts, websites, and SSL/TLS certificates.
  • VirusTotal — Online service that scans files and URLs against 60+ antivirus engines. Accepts file hashes.
  • Have I Been Pwned (HIBP) — Service that checks whether an email address appeared in a known data breach.
  • CVE (Common Vulnerabilities and Exposures) — A standardised dictionary of known security vulnerabilities. Format: CVE-YEAR-NUMBER.
  • CVE ID — The unique identifier for a specific vulnerability. Ensures consistent reference across all vendors and researchers.
  • NVD (National Vulnerability Database) — NIST's enriched CVE database with CVSS severity scores.
  • CVSS Score — Common Vulnerability Scoring System. A 0–10 score indicating a vulnerability's severity.
  • Exploit Database — Public archive of verified exploit code for known CVEs. Used by pentesters and red teamers.
  • PoC (Proof of Concept) — Code that demonstrates a vulnerability is exploitable, without necessarily being a full weaponised exploit.
  • man page — The manual page for a Linux command. Access with man <command>.
  • OPSEC (Operational Security) — Protecting information about your own activities from adversaries or unintended exposure.

What is Shodan? How is it different from Google?
Shodan is a search engine for internet-connected devices — servers, IoT, industrial systems. Google indexes web pages. Shodan indexes exposed services, open ports, and software versions on IP addresses.
What is VirusTotal used for?
Scanning files or URLs against 60+ antivirus engines simultaneously. You can also input a file hash to check previously uploaded results without re-uploading the file.
What does Have I Been Pwned tell you?
Whether an email address has appeared in a known data breach — indicating that account credentials (and potentially a password) were exposed.
What is a CVE? What format does its ID follow?
A standardised identifier for a known vulnerability. Format: CVE-YEAR-NUMBER. Example: CVE-2014-0160 (Heartbleed).
What is the Exploit Database?
A public archive at exploit-db.com listing verified exploit code for known CVEs. Maintained by Offensive Security, used by pentesters to find working exploit code.
How do you read the manual for a Linux command?
man <command> in the terminal. Example: man ip. Also searchable online by typing "man ip" in Google.
Why is LinkedIn useful for OSINT on a target company?
It reveals employees' technical backgrounds — which tools, languages, and systems they use. This helps map the organisation's tech stack and identify potential attack vectors.
What social media attack vector can overshared personal info enable?
Secret question answers (school name, pet name, etc.) used in account takeover — resetting passwords by correctly answering security questions derived from public social media posts.
What is OPSEC? Why is it relevant when doing security research on social media?
Operational Security — protecting your own activities from unintended exposure. When researching on social platforms, use temporary accounts with throwaway emails so your real identity is not linked to your recon activities.
What is the difference between Shodan and Censys?
Both index internet-connected devices. Shodan focuses on IoT and industrial systems, showing open ports and banners. Censys focuses more on hosts, certificates (SSL/TLS), and web assets — better for certificate transparency and web recon.
What is Google Dorking?
Using advanced Google search operators to find sensitive information accidentally exposed on the web — login pages, config files, leaked documents, exposed admin panels.
