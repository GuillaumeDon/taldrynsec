Packets & Frames

How data is divided into smaller pieces and transmitted across a network to another device.

01 — The Building Blocks of Data

What are Packets and Frames?

Packets and frames are small pieces of data that, when forming together, make a larger piece of information or message. They are two different things in the OSI model.

Packet (Layer 3 — Network)
A piece of data containing information such as an IP header and payload. When we talk about anything involving IP addresses, we're talking about packets.
Frame (Layer 2 — Data Link)
Encapsulates the packet and adds additional information such as MAC addresses. When the encapsulating information is stripped away, we're talking about the frame itself.

Think of it like mailing a letter: the packet is the letter (contents), the frame is the envelope (used to move the letter to another place). Once the recipient opens the envelope (frame), they know how to forward the letter (packet) itself.

Data is exchanged in small pieces rather than as a whole — this is more efficient and reduces bottlenecking on the network. For example, when loading an image from a website, it's not sent as a whole but rather in small pieces that are reconstructed on your computer.

Key Packet Headers (Internet Protocol)

  • Time to Live (TTL) — An expiry timer for the packet so it doesn't clog up your network if it never reaches its destination.
  • Checksum — Provides integrity checking for protocols such as TCP/IP. If any data is changed, this value will be different from what was expected → data is corrupt.
  • Source Address — The IP address of the device the packet is being sent from, so data knows where to return to.
  • Destination Address — The IP address the packet is being sent to, so data knows where to travel next.
Key Takeaway

Packet = has IP addressing info (Layer 3). Frame = does NOT have IP addressing info, has MAC addresses instead (Layer 2). The frame wraps around the packet like an envelope wraps a letter.

02 — Establishing Trust

TCP/IP (The Three-Way Handshake)

TCP (Transmission Control Protocol) is similar to the OSI model but consists of four layers and is arguably just a summarized version of the OSI model:

  • Application
  • Transport
  • Internet
  • Network Interface

The defining feature of TCP is that it's connection-based: TCP must establish a connection between both a client and a device acting as a server before data is sent. This guarantee means any data sent will be received on the other end.

TCP Headers

  • Source Port — The port opened by the sender to send the TCP packet from. Chosen randomly from ports not already in use (0-65535).
  • Destination Port — The port number that an application or service is running on the remote host (e.g. a webserver on port 80).
  • Sequence Number — When a connection occurs, the first piece of data transmitted is given a random number. We'll explore this in depth further.
  • Acknowledgement Number — After data has been given a sequence number, the number for the next piece of data will have the sequence number + 1.
  • Checksum — Integrity check. A mathematical calculation ensures that the output is the same. If different from what was sent → data is corrupt.
  • Data — The header is where the data (bytes of a file) that is being transmitted is stored.
  • Flag — Determines how the packet should be handled during the handshake process. Specific flags will determine specific behaviours.

The Three-Way Handshake

Before data can be sent, TCP must establish a connection. This is done through a process called the three-way handshake:

Step Message Description
1SYNInitial packet sent by a client during the handshake. Used to initiate a connection and synchronize the two devices together.
2SYN/ACKSent by the receiving device to acknowledge the synchronization attempt from the client.
3ACKAcknowledgement packet used by either client or server to acknowledge that messages have been successfully received.
4DATAOnce a connection has been established, data (such as bytes of a file) is sent via the "DATA" message.
5FINUsed to cleanly (properly) close the connection after it has been complete.
6RSTAbruptly ends all communication. This is the last resort and indicates there was some problem during the process.

Closing a Connection

To properly close a TCP connection, devices use FIN packets. Both sides must send and acknowledge a FIN. Alice sends FIN → Bob sends ACK + FIN → Alice sends ACK. The connection is now closed. Both know it's over and can release the connection state cleanly.

Sequence Numbers

Any sent data is given a random initial sequence number (ISN) and is communicated using that number sequence, incrementing by 1:

  • SYN — Client sends ISN (e.g. 0)
  • SYN/ACK — Server sends its own ISN (e.g. 5,000) and ACKs the client's: 0+1 = 1
  • ACK — Client ACKs the server's: 5,000+1 = 5,001. Data is now ISN+1 (= 1).
Key Takeaway

The three-way handshake is SYN → SYN/ACK → ACK. Think of it as: "Can you hear me?" → "Yes, can you hear me?" → "Yes!" Now the connection is open. This is fundamental to how the web works — every HTTP connection starts with this.

03 — The Fast Alternative

UDP/IP

The User Datagram Protocol (UDP) is a stateless protocol used to communicate data between devices. Unlike TCP, it doesn't require a constant connection, no three-way handshake occurs, and there is no synchronization between devices.

UDP Advantages & Disadvantages

Advantages
Much faster than TCP. Flexible for developers (app decides control). Doesn't reserve a continuous connection on a device.
Disadvantages
Doesn't care if data is received. Unstable connections = terrible experience. No built-in safeguards like data integrity.

UDP Headers

  • Time to Live (TTL) — Expiry timer so the packet doesn't clog the network.
  • Source Address — IP of the sending device.
  • Destination Address — IP of the receiving device.
  • Source Port — Randomly chosen port opened by the sender (0-65535, not already in use).
  • Destination Port — Port of the application/service on the remote host (e.g. webserver on port 80). Unlike source port, this is not chosen at random.
  • Data — Where the actual bytes of the file being transmitted are stored.

UDP packets are much simpler than TCP and have fewer headers. No acknowledgement is sent during a UDP connection — data is just fired and forgotten.

UDP Connection — Visual

Alice simply sends requests, Bob sends responses. No handshake, no ACK, no guarantee of delivery.

TCP vs UDP — Final Rule

Need a file transferred completely? → TCP. Need a video call? → UDP. TCP checks everything; UDP just sends and hopes for the best.

04 — The Doors to Services

Ports 101

Ports are an essential point in which data can be exchanged. Think of a harbour and port: ships must dock at a port compatible with their dimensions and facilities. A cruise liner cannot dock at a port made for a fishing vessel.

In computing, ports enforce strict rules when communicating. When a connection has been established, any data sent or received by a device will be sent through these ports. Ports are a numerical value between 0 and 65535 (65,535 total).

Common vs Custom Ports

Any port within 0 and 1024 (1,024) is known as a common port. These protocols only follow the standards — you can run a web server on port 8080 instead of 80, but you'll have to specify the port with a colon (:8080).

Common Ports to Memorize

Protocol Port Description
FTP (File Transfer Protocol)21File-sharing application built on client-server model. Download files from a central location.
SSH (Secure Shell)22Securely login to systems via a text-based interface for remote management.
HTTP (HyperText Transfer Protocol)80Powers the World Wide Web. Browser uses this to download text, images, and videos of web pages.
HTTPS (HTTP Secure)443Exact same as HTTP, but securely using encryption.
SMB (Server Message Block)445Similar to FTP, but also allows sharing devices like printers.
RDP (Remote Desktop Protocol)3389Securely log in to a system using a visual desktop interface (as opposed to SSH's text-based).
Key Takeaway

Memorize these 6 ports — they come up constantly in cybersecurity: 21 (FTP), 22 (SSH), 80 (HTTP), 443 (HTTPS), 445 (SMB), 3389 (RDP). Ports 0-1024 are "common ports" with standard assignments.

Vocabulary

Key Terms

  • Packet — Data with IP addressing (Layer 3, Network).
  • Frame — Data with MAC addressing (Layer 2, Data Link). Wraps the packet.
  • Encapsulation — Adding headers at each layer as data moves down the OSI stack.
  • TCP — Transmission Control Protocol. Connection-based, reliable, ordered.
  • UDP — User Datagram Protocol. Stateless, fast, no guarantee.
  • Three-Way Handshake — SYN → SYN/ACK → ACK. How TCP establishes a connection.
  • SYN — Synchronize. Initial connection request.
  • SYN/ACK — Synchronize + Acknowledge. Server's response.
  • ACK — Acknowledge. Confirms receipt.
  • FIN — Finish. Cleanly closes a connection.
  • RST — Reset. Abruptly ends all communication (last resort).
  • ISN — Initial Sequence Number. Random number assigned to first data piece.
  • TTL — Time to Live. Expiry timer for packets.
  • Checksum — Integrity check ensuring data hasn't been corrupted.
  • Port — Numbered entry point (0-65535) identifying a service on a device.
  • Common Port — Ports 0-1024 with standard protocol assignments.
  • FTP — File Transfer Protocol (port 21).
  • SSH — Secure Shell (port 22).
  • HTTP — HyperText Transfer Protocol (port 80).
  • HTTPS — HTTP Secure (port 443).
  • SMB — Server Message Block (port 445).
  • RDP — Remote Desktop Protocol (port 3389).
  • Stateless — No connection maintained between messages (UDP).
