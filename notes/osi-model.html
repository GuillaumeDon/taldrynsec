01 — The Framework

What is the OSI Model?

The OSI model (Open Systems Interconnection) is an essential framework dictating how all networked devices will send, receive, and interpret data. It has 7 layers, from Layer 7 (top) to Layer 1 (bottom).

One of its main benefits: devices can have different functions and designs on a network while still communicating with other devices, because everyone follows the same model.

At every layer that data travels through, specific processes take place and pieces of information are added. This process is called encapsulation.

Layer 1

Physical

The lowest and one of the easiest layers to grasp. This layer references the physical components of the hardware used in networking. Devices use electrical signals to transfer data between each other in a binary numbering system (1s and 0s).

Examples: ethernet cables connecting devices, fiber optic cables, Wi-Fi radio waves.

Layer 2

Data Link

Focuses on the physical addressing of the transmission. It receives a packet from the network layer and adds the physical MAC address of the receiving endpoint.

Inside every network-enabled computer is a NIC (Network Interface Card) which comes with a unique MAC address to identify it.

MAC addresses are set by the manufacturer and literally burnt into the card. They can't be changed — although they can be spoofed.

It's also the Data Link layer's job to present the data in a format suitable for transmission.

Layer 3

Network

Where the magic of routing and re-assembly of data takes place. Routing determines the most optimal path for data to travel. Protocols at this layer include:

  • OSPF — Open Shortest Path First
  • RIP — Routing Information Protocol

Factors that decide the route:

  • What path is the shortest? (fewest devices to travel across)
  • What path is the most reliable? (fewest packets lost before?)
  • Which path has the faster physical connection? (copper vs fibre)

Everything is dealt with via IP addresses at this layer. Devices like routers are Layer 3 devices because they deliver packets using IP addresses.

Layer 4

Transport

Plays a vital part in transmitting data and follows one of two protocols: TCP or UDP.

TCP — Transmission Control Protocol

  • Designed for reliability and guarantee
  • Reserves a constant connection between devices
  • Incorporates error checking — data is reassembled in the correct order
  • If one small chunk is missing, the entire chunk cannot be used
  • Significantly slower than UDP
  • Used for: file sharing, browsing, email

UDP — User Datagram Protocol

  • Not as advanced as TCP — no error checking, no guarantee
  • No constant connection — data is sent whether it arrives or not
  • Much faster than TCP
  • Flexible for developers (app layer decides control)
  • Unstable connections = terrible experience
  • Used for: video streaming, ARP, DHCP
TCP vs UDP — Quick Rule

Need accuracy (files, emails, web pages)? → TCP. Need speed and can tolerate lost data (video stream, voice call)? → UDP.

Layer 5

Session

Once data has been correctly translated (Layer 6), the session layer will create and maintain the connection to the other computer. When a connection is established, a session is created.

  • Responsible for closing the connection if idle or lost
  • Sessions can contain "checkpoints" — if data is lost, only the newest pieces need resending (saves bandwidth)
  • Sessions are unique — data cannot travel over different sessions, only across each session
Layer 6

Presentation

The layer where standardisation starts. Software developers can develop differently, but data still needs to be handled the same way — no matter how the software works.

This layer acts as a translator for data to and from the application layer. The receiving computer will understand data sent in one format even if it's destined for another format.

Security features such as data encryption (like HTTPS when visiting a secure site) occur at this layer.

Layer 7

Application

The layer you're most familiar with. This is where protocols and rules are in place to determine how the user should interact with data sent or received.

Everyday applications such as email clients, browsers, or file server browsing software like FileZilla provide a friendly GUI (Graphical User Interface) for users to interact with data.

Protocols at this layer include DNS (Domain Name System) — how website addresses are translated into IP addresses.

Summary

Encapsulation Flow

When data is sent, it travels down the layers (7 → 1), with each layer adding its own information (headers, addresses). This is encapsulation. When received, data travels up (1 → 7), with each layer stripping its information. This is de-encapsulation.

Key Takeaway

The OSI model is the language cybersecurity professionals use to discuss where attacks happen. "Layer 3 attack" = targeting IP/routing. "Layer 7 attack" = targeting the application (e.g. SQL injection, XSS). Knowing the layers = knowing where to look.

Vocabulary

Key Terms

  • OSI — Open Systems Interconnection. 7-layer networking framework.
  • Encapsulation — Process of adding information at each layer as data travels down the stack.
  • De-encapsulation — Reverse process: stripping information at each layer going up.
  • Layer 1 — Physical — Hardware, cables, binary signals (1s and 0s), ethernet cables.
  • Layer 2 — Data Link — MAC addresses, NIC (Network Interface Card), physical addressing.
  • Layer 3 — Network — IP addresses, routing (OSPF, RIP). Routers operate here.
  • Layer 4 — Transport — TCP (reliable, slow) vs UDP (fast, no guarantee).
  • Layer 5 — Session — Creates, maintains, closes connections. Checkpoints.
  • Layer 6 — Presentation — Translation, standardisation, encryption (HTTPS).
  • Layer 7 — Application — User-facing protocols (HTTP, DNS, FTP). GUI.
  • TCP — Transmission Control Protocol. Reliable, error-checked, ordered.
  • UDP — User Datagram Protocol. Fast, no error checking, no guarantee.
  • OSPF — Open Shortest Path First (routing protocol).
  • RIP — Routing Information Protocol.
  • NIC — Network Interface Card. Hardware with unique MAC address.
  • GUI — Graphical User Interface.
  • Binary — Numbering system using 0s and 1s.
